# 独立历史时点复现工具 V1.1

这个程序只回答一个问题：把现有 V6.4 股票 Agent 放回历史日期 T，当时会给出什么评分、风险和结论。

它不会读取、计算或评价 T 日之后的走势，也不会根据结果调整因子、权重或风险阈值。

## 与正式 Agent 的关系

- 正式 Agent 是被测试对象；本目录是独立测试程序。
- 本工具只导入根目录已有的 `agent_core.py`、`factor_analysis.py` 和 `news_analysis.py`。
- 不导入正式 `app.py`，不连接 Supabase，不读写正式用户、持仓或会话。
- 正式 Agent 的页面、菜单、功能、规则、因子、权重和阈值均不修改。
- 必须用单独命令启动，因此“今天=T”的临时日期只存在于测试进程，并在每次调用后恢复。

## 当前流程

1. 输入市场、股票和日期 T。
2. 行情接口的结束日期直接设为 T，仅请求约五年历史。
3. 若 T 不是交易日，使用 T 之前最近一个有个股行情的交易日。
4. 再做一次行级截断和断言，保证传给 Agent 的个股与基准日期都不晚于实际采用交易日。
5. 用 V6.4 原 `analyze_all()` 计算评分、风险、自动周期、适配、仓位和结论。
6. Agent自动给出适合的持有／复核周期，并提供结果 JSON 下载。

工具不要求用户预先填写准备观察多少天。应先让现有Agent根据T日以前的数据自动选择持有／复核周期，再由用户按照这个周期查看T日之后的真实行情，判断当时结论是否合理。

## 防未来数据规则

- 个股和基准行情的请求结束日均为 T，不先下载未来区间。
- 进入 Agent 前再次删除并检查所有日期大于 T 的行。
- `agent_core.date.today()` 只在独立测试进程的分析上下文中临时替换为实际采用交易日，退出后自动恢复。
- 当前免费源没有统一、可靠的历史披露快照，所以财务、历史利率与历史资讯暂不参与，按原 Agent 的“数据缺失”规则处理。
- 不用今天能看到的财务、宏观利率或新闻倒填历史。

注意：免费行情提供商可能事后修订复权序列。本工具保证“传入的日期行不晚于 T”，但机构级严格点时复现仍需接入带版本记录的历史行情、财务披露和资讯数据库。

## 启动

把整个 `historical_test_tool` 目录放在 V6.4 仓库根目录，与 `agent_core.py` 同级，然后单独运行：

```bash
streamlit run historical_test_tool/app.py
```

如使用 Streamlit Community Cloud，应把 `historical_test_tool/app.py` 部署为另一个独立应用，不要改正式 Agent 的入口文件。

## 测试

```bash
python -m unittest historical_test_tool.tests.test_historical_tool -v
```
